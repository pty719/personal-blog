## 1. 项目背景（为什么做）

目标是智能体开发工程师——需要一个**能拿出手的完整作品**：既能练全栈（前端/后端/数据库/部署），又能把 Agent 技术（ReAct/RAG/工具调用/自动化）真正落地。所以做了这个网站：表面是博客，实际是 Agent 技术的试验田。

## 3. 功能架构（三层）

```
基础层：文章/说说/友链/项目管理 + JWT 登录 + 管理后台（CRUD/搜索/分页/批量删除）
Agent 层：
  ├ AI 助手（ReAct 循环 + 工具调用 + SSE 流式 + 会话记忆 + RAG 语义检索）
  ├ AI 新闻采集（定时爬取 RSS → 入库 → 展示，每 6 小时）
  ├ 友链监控（定时 HEAD 探测友链存活 → 失效标记）
  └ 文章 AI 摘要（发布时自动总结 50 字）
工程层：限流三件套（防刷烧钱）/ 密钥环境变量化 / 生产事故复盘（MySQL 内存限制）
```

## 4. 核心 Agent 功能详解（面试重点）

### 4.1 AI 助手（ReAct 循环）

```
流程：用户提问 → 完整历史发给 DeepSeek（LLM 无状态）→ 模型看 TOOLS 说明书决策
  → 直接回答 或 返回 tool_calls → call_tool 执行 → 结果 role=tool 消息（带 tool_call_id）
  → 再发一轮（模型"读"结果组织回答）→ 最多 5 轮防死循环
```

- **工具注册**：TOOLS = 工具说明书（name/description/parameters 入参）——告诉模型"怎么调"，不是返回类型
- **双层循环**：外层 5 轮 = ReAct 轮次；内层 = 一条回复多个工具逐个执行、每个结果 append 一条
- **事件流**：event_stream 生成器 yield {type: tool/text/done} → StreamingResponse SSE 推送 → 前端逐字渲染 + 工具调用透明化（📚 检索知识库提示）
- **会话记忆**：conversation_id（uuid）→ SSE 首条事件给前端 → localStorage → 每次请求带 id → MySQL 查历史拼进 messages；长对话设计阈值摘要压缩（早期压缩/近期保留）
- **RAG（TF-IDF → embedding 升级）**：
  - 切块（200 字）→ 每块向量化 → numpy 余弦检索 top3 → 拼进提示词带来源
  - 升级原因：TF-IDF 字面匹配（"变化率"匹配不到"导数"）；embedding 语义向量（同义词方向相近可命中）
  - 选型：fastembed + bge-small-zh（约150MB）vs torch 方案（800MB）——2G 服务器资源权衡
  - 演进：块少用 numpy；量大换 FAISS/Chroma（架构解耦接口不变）

### 4.2 AI 新闻采集（信息采集 Agent）

- 源选型：RSSHub 公共实例实测被墙 → curl 实测换源 → hnrss.org q=AI（Hacker News）
- 管线：feedparser 解析 → url 去重（代码层 + 数据库 unique 双保险）→ clean_html 去标签 → 时间解析（parsedate_to_datetime 防御单条失败）
- 定时：APScheduler interval（每 6 小时）vs cron（友链巡检每天 8:00 定点）——触发器场景选择

### 4.3 友链监控 / 文章摘要

- 友链：APScheduler cron + httpx HEAD 探测 + is_active/last_check 字段（建表时就预留——字段设计前瞻性）
- 摘要：发布文章时 LLM 生成（LLM 嵌入业务管道——不只是聊天）；try/except 兜底（生成失败 ≠ 发布失败，截断兜底）

## 5. 工程化与生产（简历加分项）

| 项 | 细节 |
|---|---|
| 限流三件套 | Pydantic 长度校验（422）→ IP 限流 10 次/分（429，生产换 Redis）→ 会话轮数 100 条；原则：全部在调 LLM 之前（花钱边界） |
| 生产事故 | MySQL 默认配置跑一周内存耗尽卡死 → 排查（unhealthy → 日志 → semaphore wait → free -m）→ 显式限内存（buffer 64M/连接 50/关 performance schema）→ 写进 compose 预防 |
| 密钥安全 | DeepSeek key/JWT/MySQL 密码全部环境变量化（.env + compose 注入 + dockerignore 排除）——代码零密钥 |
| git | 项目根仓库 + .gitignore 隔离敏感文件（.env/blog.db/.bak），提交前 check-ignore 验证 |
| 数据 | 文章/说说/友链/项目/assistants（对话）/ai_news 六张表 |
