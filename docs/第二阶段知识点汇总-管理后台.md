## 1. axios 为什么值得学（vs 原生 fetch）

| 对比 | fetch（之前用的） | axios（现在用的） |
|---|---|---|
| 拦截器 | ❌ 没有 | ✅ **请求前/响应后统一处理** |
| 自动带 token | 每个请求手写 headers | 拦截器一次配置，全局生效 |
| 错误处理 | 手动判断 `res.ok` | 响应拦截器统一处理 401 |
| 返回数据 | `res.json()` 手动解析 | 拦截器直接返回 `data` |
| 超时设置 | 手写 AbortController | `timeout: 10000` 一行 |
| 兼容性 | 现代浏览器 | 老浏览器也兼容 |

**面试答"为什么用 axios"**：①拦截器可以做全局的 token 注入和错误处理，②统一配置 baseURL/超时，③返回数据自动解析——**多接口项目里避免重复代码**。

## 2. axios 实例 + 拦截器（核心中的核心）

代码位置：`src/api/request.js`

### 2.1 创建实例（带默认配置）

```js
const request = axios.create({
  baseURL: '/api',      // 写 '/moments' 自动变成 '/api/moments'
  timeout: 10000,       // 10 秒超时
})
```

**为什么 baseURL='/api'**：开发时走 Vite 代理（`vite.config.js`），部署时走 nginx 反代——**前端代码永远不用改**。这是前后端分离的标准做法。

### 2.2 请求拦截器（发请求前）

```js
request.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`   // 自动带 token
  }
  return config
})
```

**时序**：`页面调用 request.post(...)` → **拦截器**（加 token）→ 真正发请求 → 后端收到带 Authorization 的请求。

**解决了你之前的痛点**：以前每个请求手动加 `Authorization` 头（Swagger 里折腾半天的那个），现在**一次配置，所有接口自动带**。

### 2.3 响应拦截器（收到响应后）

```js
request.interceptors.response.use(
  (res) => res.data,      // 成功：直接拿数据
  (err) => {
    if (err.response?.status === 401) {        // token 失效
      localStorage.removeItem('token')          // 清登录态
      window.location.href = '/login'           // 踢回登录页
    }
    return Promise.reject(err)                  // 其他错误抛给调用方
  }
)
```

**401 统一处理**：任何接口返回 401（token 过期/被篡改）→ 自动清 token 跳登录页——**不用每个接口都写一遍**。

## 3. localStorage 与登录态

### 3.1 token 存哪里（三种存储对比）

| 存储 | 特点 | 适合 |
|---|---|---|
| **localStorage** | 持久（关浏览器还在）、纯前端读写 | ✅ 项目用的：token 存这 |
| sessionStorage | 关标签页就清 | 临时数据 |
| cookie | 每次请求自动带、可设 HttpOnly | 传统方案 |

### 3.2 为什么存 localStorage + 手动带头

我们选择：**token 存 localStorage，每次请求由拦截器手动放进 Authorization 头**。

**面试考点（必背）**：
- **XSS 风险**：localStorage 里的 token 能被页面里的恶意脚本读走（`localStorage.getItem('token')`）→ 所以**永远不要用 `v-html` 渲染用户输入的内容**（你文章详情页用的 `v-html` 是渲染自己数据库的内容，可控）
- **cookie + HttpOnly 更安全**：HttpOnly 的 cookie 脚本读不到，但实现复杂（CSRF 防护等）
- **生产方案**：大厂多用 HttpOnly cookie + CSRF token；小项目 localStorage 够用——**能说出两者的取舍，面试就加分**

### 3.3 登录态三件套

```js
localStorage.setItem('token', data.access_token)   // 登录：存
localStorage.getItem('token')                       // 请求/守卫：读
localStorage.removeItem('token')                    // 退出/401：清
```

## 4. v-model 双向绑定（表单核心）

代码位置：`LoginView.vue`

```vue
<input v-model="username" type="text" placeholder="用户名" />
```

**v-model = 语法糖**，等价于：

```vue
<input :value="username" @input="username = $event.target.value" />
```

- `:value`：数据 → 输入框（数据变化，框里变）
- `@input`：输入框 → 数据（用户打字，数据跟着变）
- 两个方向都通 = "双向绑定"

**面试问"v-model 原理"**：答上面这个语法糖展开，再说 `.number`/`.trim` 修饰符就完整了。

## 5. 事件处理（交互入口）

```vue
<button @click="handleLogin">登录</button>          <!-- 点击 -->
<input @keyup.enter="handleLogin" />                 <!-- 回车触发（表单体验） -->
<form @submit.prevent="handleLogin">...</form>       <!-- 表单提交标准写法（prevent=阻止默认刷新） -->
```

要点：
- `@click` / `@keyup.enter` / `@submit.prevent` 都是事件绑定，`@` 是 `v-on` 缩写
- `.prevent` = 阻止浏览器默认行为（表单提交会刷新页面，必须阻止）
- `:disabled="loading"` 防止重复提交（登录中按钮置灰）

## 6. 路由守卫（进行中：改完 router 生效）

代码位置：`router/index.js`

```js
// 每次路由跳转前都会执行
router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  if (to.path.startsWith('/admin') && !token) {
    return '/login'        // 未登录访问后台 → 踢去登录页
  }
  if (to.path === '/login' && token) {
    return '/admin'        // 已登录还访问登录页 → 直接进后台
  }
  // 其他情况放行
})
```

**三个分支逻辑**：
| 情况 | 去向 |
|---|---|
| 访问 /admin 且没 token | → /login |
| 访问 /login 且有 token | → /admin |
| 其他 | 放行 |

**⚠️ 面试重点：前端守卫 ≠ 安全**：
- 路由守卫只是**用户体验优化**（未登录看不到后台页面）
- **真正的安全在后端**：接口的 `Depends(get_current_user)` 才是防线（没 token 直接 401）
- 前端代码全在用户浏览器里，可被绕过——**永远假设前端可被攻破，后端必须自保**（你的 FastAPI 接口都有鉴权，这就是正确的架构）

## 7. 完整登录闭环（把整个阶段串起来）

```
用户访问 /admin
  ↓ 路由守卫：没 token？→ 跳 /login
登录页填账号密码 → request.post('/auth/login')
  ↓ 后端验证密码 → 返回 token
localStorage.setItem('token', ...) → router.push('/admin')
  ↓ 后台页面发请求（发文章/发说说）
request 拦截器自动加 Authorization: Bearer <token>
  ↓ 后端 get_current_user 验证通过 → 接口执行
token 过期/被改 → 后端 401
  ↓ 响应拦截器：清 token → 跳 /login
```

**这套闭环 = 全栈鉴权的标准形态**，你能讲清楚它，面试的"登录鉴权"题就稳了。
