## 2. 核心知识模块

### 2.1 项目结构（FastAPI 标准分层）

```
app/
├── main.py      入口：FastAPI 实例 + CORS + 路由挂载
├── config.py    配置：DATABASE_URL / JWT_SECRET（pydantic-settings）
├── db.py        引擎 + 会话（engine / SessionLocal / Base / get_db）
├── models.py    ORM 模型（5 张表）
├── schemas.py   Pydantic 输入输出契约
├── auth.py      密码哈希 + JWT 签发/校验
└── routers/     业务路由（一个资源一个文件）
```

**核心认知：models（数据库长什么样）和 schemas（接口长什么样）分离——FastAPI 最佳实践。**

### 2.2 SQLAlchemy 2.0 ORM 风格（vs 你以前的 Core 风格）

| 操作 | Core 风格（session.execute） | ORM 风格（本项目） |
|---|---|---|
| 查全部 | `db.execute(select(X)).scalars().all()` | `db.query(X).all()` |
| 按主键 | `db.get(X, id)` | `db.get(X, id)` |
| 计数 | `select(func.count())...` | `db.query(X).count()` |
| 插入 | `db.add(x); db.commit()` | 同左 |
| 取结果 | Row 对象，`.scalar()` | **ORM 对象，直接 `.属性`** |

**结论：ORM 风格更直观——查出来就是对象，直接点属性。项目内保持一种风格最重要。**

### 2.4 Pydantic 分工（Create vs Out）

```python
class MomentCreate(BaseModel):          # 客户端"能传什么"
    content: str = Field(min_length=1, max_length=500)
    images: str = ""

class MomentOut(BaseModel):             # 服务器"返回什么"
    model_config = ConfigDict(from_attributes=True)   # 允许 ORM 对象直接转
    id: int
    content: str
    images: str
    created_at: datetime
```

**铁律：Create 只放客户端有资格传的字段**——id/created_at/is_active 是服务器字段，进 Create 就 422 或会被客户端篡改。

**422 vs 400**：Pydantic 校验失败 = **422**（FastAPI 标准）；主动 raise 的业务错误（密码错）= 400。

### 2.5 CRUD 标准套路（每个接口三步）

| 操作 | 查 | 写 | 回 |
|---|---|---|---|
| 列表 | `count()` + `order_by + offset + limit` | — | `{total, page, page_size, items}` |
| 创建 | — | `add + commit + refresh` | 返回对象（201） |
| 删除 | `db.get` 判空 | 空 → 404；`delete + commit` | 无返回体（204） |

**`db.refresh()` 的作用：把数据库生成的值（id/created_at）刷进对象。**

### 2.6 JWT 鉴权（认证闭环）

```python
# 签发（login 接口）：sub=用户id，exp=过期时间
jwt.encode({"sub": str(user.id), "exp": ...}, JWT_SECRET, algorithm="HS256")

# 校验（依赖函数，挂在需要登录的接口上）
def get_current_user(authorization: str = Header(default=""), db=Depends(get_db)):
    if not authorization.startswith("Bearer "): raise 401    # 格式
    payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])  # 验签+过期
    user = db.get(User, payload["sub"])                       # 查用户
    return user
```

**用法：`user: User = Depends(get_current_user)` —— 接口执行前先验 token，失败 401 不执行。**

**JWT 结构（面试必答）**：`Header.Payload.Signature` 三段，base64 可读（**绝不能放密码**），签名防篡改。

## 3. 踩坑记录（后端，血泪教训）

| # | 坑 | 症状 | 原因 | 解决 |
|---|---|---|---|---|
| 1 | `@router.post("/")` 多斜杠 | 前端请求 405 | 列表无斜杠、POST 带斜杠，路径不一致 | 统一 `@router.post("")` |
| 2 | 创建接口返回 200 | 语义不对 | status_code 默认 200 | 创建 = `status_code=201` |
| 3 | Create 里有服务器字段 | 422 missing is_active | is_active/created_at 进了 Create | Create 只收客户端字段 |
| 4 | `db.get(Friend, project_id)` | 删"项目"删了友链 | 复制粘贴查错表 | 检查：函数名/查的表/返回 schema/文案 |
| 5 | `FriendOut.last_check: datetime` | 有数据就 500 | 数据库是 NULL，非空校验失败 | 可空字段写 `datetime \| None = None` |
| 6 | 排序不稳定 | 同秒数据顺序乱 | created_at 精确到秒 | `order_by(created_at.desc(), id.desc())` 双条件 |
| 7 | 校验失败期望 400 | 实际 422 | FastAPI 标准行为 | 422 是 Pydantic 校验；400 是自己 raise 的业务错误 |
| 8 | 后端"莫名其妙"在跑 | 忘了哪个窗口 | uvicorn 是独立终端跑的，不在 PyCharm | `netstat -ano \| findstr :8000` 查 PID |
| 9 | docstring 写 `\uvicorn` | SyntaxError | `\u` 被当 Unicode 转义 | Windows 路径写正斜杠 |

## 6. 面试速记（后端部分）

| 问题 | 回答 |
|---|---|
| FastAPI 为什么流行？ | 自动 OpenAPI 文档（Swagger）、Pydantic 校验、异步支持、类型提示友好 |
| ORM 和原生 SQL 区别？ | ORM 防注入、对象化；复杂查询用原生 SQL/核心 API |
| JWT 和 Session 区别？ | JWT 无状态（服务器不存）、可水平扩展；Session 存服务器、可控注销 |
| JWT 里放什么？ | 用户 id（sub）+ 过期时间；**绝不放密码** |
| 密码怎么存？ | bcrypt 哈希 + 随机盐（本项目）；绝不存明文 |
| 422 和 400 区别？ | 422 校验失败（Pydantic）；400 业务错误（自己 raise） |
| 分页怎么实现？ | `offset((page-1)*page_size).limit(page_size)` + count() |
| 怎么防 SQL 注入？ | ORM 参数化绑定（`?` 占位符 / filter 条件），不拼字符串 |
