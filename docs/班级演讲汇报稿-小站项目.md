# 《我的个人博客网站——从 0 到 1 做一个带 AI 助手的全栈项目》演讲稿（5 分钟版）

> 汇报人：yizhiyu ｜ 项目：小站（FastAPI + Vue3 + MySQL + Docker + Agent）

## 一、开场（约 40 秒）

各位老师、同学们，大家好。今天我想跟大家分享的，是我这段时间做的一个项目——一个部署在公网上的个人博客网站。

先说说我为什么做它。我来学智能体开发，目标是以后做 Agent 方向的工程师。但光听课是不够的，我想做一个**能拿得出手的完整作品**——既能练全栈，又能把我学的智能体技术真正用起来。所以就有了这个项目：它表面上是个博客，实际上，它是我的一个"试验田"。

## 二、项目整体介绍（约 1 分钟）

先讲整体。技术栈是前端 Vue 3、后端 FastAPI、数据库 MySQL，用 Docker 部署在我自己的阿里云服务器上——同学们现在用手机打开网址，全球任何地方都能访问。

功能上分两块：一块是博客的基础功能——文章、说说、友链、项目展示，带登录的管理后台，可以发布文章、管理内容，文章列表还支持搜索、分页、批量删除。

另一块，是我花心思最多的部分——三个"智能"功能。这块我详细讲讲，也是我最想跟大家交流的地方。

## 三、三个智能功能（约 2 分钟）

**第一个，是站内的 AI 助手。** 它不是一个一问一答的聊天机器人，而是一个会"自己干活"的智能体。核心思想叫 ReAct——Reason 和 Act，就是让模型"想一下 → 决定要不要用工具 → 用工具拿到结果 → 再回答"这样一个循环。

举两个真实例子：你问它"我的网站里有什么文章"，它会自己去数据库查，把结果列给你；你问它"我写过关于微积分的内容吗"，它会去检索我的文章知识库——这个检索叫 RAG，意思是"检索增强生成"：我把文章切成小块、做索引，它先找到最相关的内容，再基于真实内容回答。所以它不会瞎编，回答还带着来源。另外它还有记忆——聊过的内容存在数据库里，刷新页面接着聊，它都记得。

**第二个功能，是发布文章时自动生成摘要。** 我写完一篇长文章，AI 自动帮我总结出 50 字以内的摘要。这个功能让我意识到：大模型不只是拿来聊天，它可以嵌进业务流程里，帮人省时间。

**第三个，是一个"值守"程序。** 它每天定时自动检查我友链里的网站是不是还活着，挂掉的自动标记出来。虽然功能小，但它是我做的第一个"主动干活"的程序——不需要用户点，到点自己跑。

## 四、部署与踩坑（约 1 分钟）

项目最折腾的不是写代码，是部署上线。我踩了两个大坑，印象特别深。

第一个坑：我的服务器只有 2G 内存，第一次上线跑了一周，数据库直接把服务器卡死了，网站全挂。我排查发现，是小内存机器上数据库默认配置太吃内存，运行时间越长占用越高，最后把内存耗尽。解决方法是给数据库显式限制内存占用——现在稳定多了。这件事让我真正理解了：**生产环境和本地完全不一样，资源是要算账的**。

第二个坑：AI 助手某天突然不回答问题了，排查了很久，最后发现是底层一个公共函数的返回值类型设计得不合理——两个地方调用同一个函数，一个要字符串、一个要对象，互相打架。这也让我明白：**公共函数的"接口设计"比写功能本身更重要**。

## 五、收获与不足（约 40 秒，谦虚收尾）

做完这个项目，我最大的收获其实不是"会了哪些技术"，而是建立了两个意识：一个是**工程意识**——代码要能上线、要防别人刷接口、密钥要藏好、要记录问题；另一个是**排查意识**——出了问题怎么一步步定位，而不是瞎猜。

当然，这个项目还有太多不足。我只是刚入门，代码结构、工程规范离工业级还差得很远，RAG 用的也是最基础的方案。能做出这些，离不开老师的教导和同学们的交流，真的非常感谢大家。

接下来我会继续完善它，也多听听大家的意见。我的分享就到这里，谢谢大家！

## 附录 1：3 分钟精简版（备用，限时用）

各位老师、同学们好。今天分享我做的项目——一个部署在公网的个人博客网站，但它不是普通博客，里面藏着一个会"自己干活"的 AI 助手。

技术上：Vue3 前端 + FastAPI 后端 + MySQL + Docker 部署到阿里云。基础功能有文章、说说、友链、项目和管理后台。重点说三个智能功能：

一是站内 AI 助手，核心思想叫 ReAct——让模型"想一下、决定要不要用工具、拿到结果再回答"。你问它站里有什么文章，它自己去数据库查；问它有没有写过某类内容，它会检索文章知识库（RAG）基于真实内容回答，不瞎编，还有记忆。

二是发文章自动生成 AI 摘要，写完长文自动总结 50 字。

三是定时值守程序，每天自动检查友链网站死活。

最折腾的是部署：2G 内存服务器被数据库卡死过，排查发现是小机器上数据库默认配置吃内存，限制后解决。还有一次 AI 不回答了，最后发现是公共函数返回类型设计不合理。

收获：不只是技术，更是工程意识（能上线、防刷、藏密钥）和排查意识。项目还很粗糙，感谢老师同学，谢谢大家！

## 附录 2：提问预判与应对

| 可能的问题 | 建议回答 |
|---|---|
| AI 助手原理能再讲讲吗？ | 用比喻：像秘书——你说需求，它想想要不要查资料，查完再答复你（ReAct 一句话版） |
| RAG 是什么？为什么需要？ | 大模型不知道你私有的文章内容，直接问会瞎编；RAG = 先检索出相关文章片段，拼进提示词再回答，带来源、不瞎编 |
| 这项目是你独立完成的吗？ | 诚实谦虚："在课程所学基础上，遇到不会的查资料、请教，一步步独立做完的" |
| 最大的收获是什么？ | "从会写代码到会排查问题——真正的开发不只是写功能，还要能上线、能定位问题" |
| 会话记忆怎么做？ | 对话存数据库（会话 id + 角色 + 内容），每次请求把历史带上；游客用浏览器本地存储记会话 id |
| 怎么防别人恶意调用烧钱？ | 三层：输入长度限制、IP 限流（超限返回 429）、每日全局预算；检查都在调大模型之前 |
| 部署最难的点？ | 2G 小内存机器资源规划：数据库默认配置会 OOM，需显式限制内存；Docker 依赖必须完整 |

## 附录 3：背诵建议

- 背"骨架"：五段标题 + 每段要点词（开场动机 / 两块功能 / 三个智能 / 两个坑 / 双意识收获）
- 内容用自己的话展开，不要逐字背（忘词会慌）
- 关键术语准备"人话解释"（ReAct = 秘书查资料再回答；RAG = 先找书再答题）
- 演讲前对着镜子/手机录一遍，掐时间（5 分钟版控制在 4:30-5:00 最佳）
