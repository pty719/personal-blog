# 前端排错必备：Network 网络面板诊断教程

> 适用浏览器：Edge / Chrome（你的 Edge 和 Chrome 的开发者工具几乎一样）
> 目的：页面出问题时，用 5 分钟定位"是前端代码、后端接口、还是数据字段"的锅
> 触发场景：白屏、报错、数据不显示、页面慢——先看 Network，再猜代码

---

## 1. 打开开发者工具（3 种方式任选）

| 方式 | 操作 |
|---|---|
| 快捷键 | 页面里按 **F12**（或 `Ctrl + Shift + I`） |
| 菜单 | 浏览器右上角 ⋮ → 更多工具 → 开发者工具 |
| 右键 | 页面空白处右键 → 检查 |

打开后是一块停靠在右侧/底部的面板，顶部有标签：

```
元素 | 控制台 | 源代码 | 网络(N) | 性能 | 应用程序 ...
```

**本教程只讲「网络」(Network)**——看浏览器和服务器之间发生了什么。

---

## 2. Network 面板界面认识

点「网络」标签，你会看到：

```
┌─────────────────────────────────────────────────────────┐
│ 🚫(清空)  ⏺(录制)  筛选: 全部|Fetch/XHR|文档|图片|...     │
├─────────────────────────────────────────────────────────┤
│ 名称            状态     类型      耗时    大小           │
│ api/moments     200     fetch     38ms   1.2KB    ← 请求列表 │
│ api/articles    200     fetch     11ms   900B            │
│ cc-img...jpg    200     img       1.9s   128KB   ← 红色=慢 │
│ favicon.ico     404     document  <1ms   —       ← 红色=错 │
├─────────────────────────────────────────────────────────┤
│ 点击任意一行 → 右侧/下方出现详情面板                        │
└─────────────────────────────────────────────────────────┘
```

**关键概念**：
- **状态列**：200=成功，404=找不到，500=服务器出错，红色=有问题
- **耗时列**：哪个请求慢一目了然（图片 1.9s 就是之前说说的"凶手"）
- **筛选栏**：`Fetch/XHR` = 只看接口请求（页面里的 fetch/axios），最常用

---

## 3. 完整诊断流程（5 步，核心）

### 第 1 步：清空记录 + 打开 Network

1. 点「网络」标签
2. 点左上角 **🚫 清空** 按钮（把旧记录清掉，只看接下来的请求）
3. **保持 Network 面板开着**（别关）

### 第 2 步：刷新页面

按 **F5**（或 Ctrl+Shift+R 强刷）。页面发出的所有请求会一条条出现在列表里。

### 第 3 步：筛选目标请求

点筛选栏的 **Fetch/XHR**（只看接口），找到你想查的请求（比如 `api/moments`）。

### 第 4 步：看它实际返回了什么（最关键！）

点击该请求 → 右侧详情面板 → 点 **响应 (Response)** 标签：

```
Response 显示后端返回的原始 JSON，例如：
{"total":4,"page":1,"page_size":10,"items":[
  {"id":4,"content":"准备开始说说页...","images":""},   ← 注意：没有 created_at！
  ...
]}
```

**这一步回答的问题："后端到底给了前端什么？"**

### 第 5 步：对比前端期望的字段

前端代码用了什么字段，Response 里就得有什么字段：

```
前端写：moment.created_at.slice(0, 10)
后端返回：{"id":4,"content":"...","images":""}   ← 没有 created_at → undefined → 报错！
```

**字段契约对不上 = 前端 undefined 报错 / 数据不显示。** 这就是你刚踩的坑。

## 4. 常见问题 → 一眼判断表

| Network 里的现象 | 问题在哪 | 怎么修 |
|---|---|---|
| 请求**红色失败** `ERR_NAME_NOT_RESOLVED` | 域名拼错 / 网络断 | 检查 URL 拼写 |
| 状态 **404** | 路径错了（后端没这个接口/前端拼错） | 对比 router 和接口路径 |
| 状态 **500** | **后端代码报错** | 看后端终端（uvicorn 控制台）的红色 Traceback |
| 状态 **401** | 没登录 / token 没带 / Bearer 没空格 | 检查请求头 Authorization |
| 状态 **422** | 参数校验失败（缺字段/格式错） | 看 Response 里的 detail 提示 |
| 状态 **200 但字段缺失** | 前后端字段契约不一致 | 对比前端用的字段 vs Response 返回字段 |
| 某个请求**耗时特别长**（>1s） | 图片/第三方资源 | 换图床/加懒加载/上 CDN |
| 200 但页面还是空 | 前端渲染逻辑（v-if 条件、数组为空） | 看 Console 报错 + 数据有没有进页面 |

> 口诀：**先看 Network 定位请求，再看 Response 对比字段，最后才怀疑代码逻辑。**

## 5. 实战案例：你的 created_at 问题（完整走一遍）

1. 打开 `http://localhost:5173/moments` → 按 F12 → 网络标签
2. 看到控制台报错 `Cannot read properties of undefined (reading 'slice')`
3. 点筛选 Fetch/XHR → 点 `api/moments` 请求 → 响应标签
4. 看到返回 JSON 里确实**没有 created_at**
5. 结论：后端 `MomentOut` schema 缺字段 → 去 `schemas.py` 加回 `created_at: datetime`
6. 修好 → 强刷 → Network 里 Response 出现 created_at → 页面正常

**这就是完整的前后端联调排错闭环。**

## 6. 实用技巧（进阶）

### 技巧 1：看请求头（验证 token 有没有带上）

点请求 → 详情面板 → **请求头 (Headers)** 标签 → 往下找：

```
authorization: Bearer eyJ...   ← 有这行 = token 带上去了；没有 = 前端忘了带
```

之前你的 Authorization 问题，在这里一眼就能确认"到底发没发出去"。

### 技巧 2：保留日志（跳转页面不丢记录）

Network 面板勾选 **保留日志 (Preserve log)**——页面跳转/刷新后旧请求不消失，适合排查"登录后跳转"的流程。

### 技巧 3：复制为 cURL（把浏览器请求变成命令）

右键某个请求 → 复制 → **以 cURL 格式复制**——拿到完整命令（含所有请求头），粘贴到终端就能复现，发给别人排查问题。

### 技巧 4：禁用缓存（改代码不生效时）

勾选 **禁用缓存 (Disable cache)** + 强刷——绕过浏览器缓存，永远加载最新代码。

## 7. 练习任务（5 分钟）

用今天学的方法自己诊断一次：

1. 打开 Network → 清空 → 刷新 `http://localhost:5173/moments`
2. 找到 `api/moments` 请求，回答 3 个问题：
   - 状态码是多少？（应该 200）
   - 耗时多少 ms？（应该 <100ms）
   - Response 里有 `created_at` 字段吗？（修复后应该有）
3. 再找一个**图片请求**，看它的耗时（应该有图片或者已经没有图片了）

**能独立回答这 3 个问题 = 你已经会看 Network 了**，以后任何"页面不对"都能自己定位 80% 的问题。

## 8. 常见困惑 FAQ

| 问题 | 回答 |
|---|---|
| 我的是 IE 不是 Edge？ | 你截图显示用的是 Edge（微软新版），Edge/Chrome 的 F12 一样。老 IE 已停止支持，别用 |
| 为什么我 F12 打开没有「网络」标签？ | 点标签行最右边的 `>>` 展开更多标签 |
| Network 里什么都没有？ | 确认没勾选筛选、清空过、然后刷新页面 |
| 怎么看 JSON 更清楚？ | Response 标签下有「预览 (Preview)」视图，可折叠展开看结构 |
| 接口 200 但页面空白？ | 看「控制台」标签的红色报错 + 确认数据有没有进 ref（Console 里打印） |

## 9. 排错总流程（贴显示器上）

```
页面出问题
  ├─ F12 → 控制台：有红色报错？→ 读报错（undefined/404/语法）
  ├─ F12 → 网络：哪个请求红/慢？
  │     ├─ 500 → 后端终端看 Traceback
  │     ├─ 404 → 路径拼错
  │     ├─ 401 → 请求头 Authorization
  │     └─ 200 但字段缺 → Response 对比前端字段
  └─ 以上都正常 → 才是前端渲染逻辑（v-if/v-for/数组）
```
