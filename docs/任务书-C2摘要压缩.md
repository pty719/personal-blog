# 任务书 C2：对话摘要压缩（>20 条自动压缩早期对话）

> 目标：控制长对话的请求体 token 不无限膨胀（LangChain summary memory 同款思路）
> 状态：设计文档 ｜ 预计 2-3 小时 ｜ 核心代码自己写（Agent 记忆 = 面试重点）

---

## 1. 为什么做（动机）

```
对话到第 30 轮：messages 历史 60+ 条 → 每次请求全量发给 DeepSeek
→ token 随轮数线性增长 → 请求体膨胀 → 慢 + 烧钱
解决：早期对话压成"摘要"，只保留最近几轮完整
→ 请求体大小基本恒定（summary + 最近 N 条）
```

**面试价值**：这是 LangChain 的 Summary Memory / 滑动窗口压缩的工程实现——"我实现了对话摘要压缩，控制 token 成本"是实打实的加分项。

## 2. 方案设计

### 2.1 存储：复用 assistants 表，role 加一种类型

```
assistants 表（已有）：conversation_id / role / content / created_at
role 取值：'user' | 'assistant' | 'summary'（新增——一条压缩后的对话摘要）
→ 不用新表！同表不同 role（查询时 role='summary' 也是历史的一部分）
```

### 2.2 触发条件

```
chat 接口查完历史后：
len(history) > 20 条 → 触发压缩（20 条 ≈ 10 轮对话）
```

### 2.3 压缩动作（核心函数 compress_history）

```
取"最早的旧消息"（不含最近 5 条）→ 调 DeepSeek 压成一段 summary
→ 摘要存一条 role='summary' 消息 → 物理删除被压缩的旧消息
→ 下次请求历史 = [summary] + 最近完整消息
```

### 2.4 再次压缩（滚动摘要——关键设计）

```
历史 = [summary, m6, m7, ..., m25]（21 条 > 20）→ 再触发
处理：把【已有 summary + 之后最早的旧消息】一起压成新 summary
→ 摘要滚动更新，不重复压缩已摘要内容
（注意：summary 不是普通消息，压缩时要带上它一起，别丢）
```

### 2.5 压缩失败兜底

```
DeepSeek 挂了/超时 → 不压缩，全量历史照常发给模型（降级不炸）
→ 压缩是优化不是依赖（和文章摘要同一哲学）
```

## 3. 流程时序（第 21 次提问触发）

```
用户提问
→ chat 接口：conv_id 查历史 → 存 user 消息
→ len(history) > 20？
   是 → compress_history(最早 15 条 + 已有 summary)
        → LLM 压成 100 字摘要 → 存 role='summary'
        → 删除被压的旧消息
→ messages = [system] + [summary] + 最近完整消息
→ event_stream → DeepSeek 回答（无感——用户不知道发生过压缩）
```

## 4. 任务书（分步）

### ① assistants.py 加 compress_history(history) 函数
```python
def compress_history(history) -> list:
    """压缩早期消息 → 返回新历史（summary + 剩余完整）"""
    # 1. 分离：history 里 role='summary' 的（已压缩部分）+ 普通消息
    # 2. 如果普通消息 <= 5 条：不用压，直接返回
    # 3. 要压的 = 已有 summary（如有）+ 最早的 (总条数 - 5) 条普通消息
    # 4. 调 chat_completion 压缩成摘要（提示词见下）
    # 5. 返回 [summary消息, *剩余完整消息]
```

**压缩提示词**（你写，参考）：
```
"把下面的对话压缩成一段 120 字以内的摘要，保留：用户问过什么、助手回答的要点、涉及的主题。不要遗漏用户还没解决的问题：\n{要压缩的对话}"
```

### ② chat 接口接入（压缩在存 user 消息后、查完历史后）
```python
if len(history) > 20:
    new_history = compress_history(history)   # 压缩（含 LLM 调用）
    # 删被压旧消息（db 里 role 非 summary 的早期消息）
    # 存新 summary
    history = new_history   # 用压缩后的历史拼 messages
```

## 6. 面试话术（做完后）

> "长对话我会做摘要压缩：超过 20 条消息时，把最早的对话调 LLM 压成 summary 存库（role=summary），请求历史变成 summary + 最近几条——token 基本恒定。再次超阈值时把已有 summary 和新消息一起滚动压缩。压缩失败就降级全量发送——压缩是优化不是依赖。这和 LangChain 的 Summary Memory 是一个思路。"

## 7. 边界与坑（先看）

| 情况 | 处理 |
|---|---|
| 已有 summary 再压缩 | summary 要带上一起滚动压缩（别丢） |
| DeepSeek 压缩失败 | 不压缩，全量发送（降级） |
| 压缩时的 LLM 调用 | 会慢 1-3 秒（只在超阈值时发生，可接受） |
| 摘要质量 | 提示词要求"保留未解决问题"（用户可能接着问） |
| summary 别当普通消息处理 | 压缩函数里先分离 role='summary' |
