## 3. 面试 10 问（含回答要点）

### Q1：你的 AI 助手怎么实现的？
**要点**：ReAct 循环（LLM 决策→工具调用→观察结果→再决策，最多 5 轮）→ 工具注册（function calling 格式）→ SSE 流式（生成器 yield 事件：tool/text/done）→ 前端 getReader 解析。

### Q2：RAG 的原理？你为什么不直接用 LLM 回答？
**要点**：LLM 不知道私有数据 → 检索增强：切块（200 字）→ 索引（jieba 分词 + TF-IDF）→ 检索（相似度 top3）→ 增强（拼提示词）。**无 RAG = 瞎编；有 RAG = 带来源回答**。

### Q3：为什么用 TF-IDF 不用向量数据库？
**要点**：MVP 验证全流程（零依赖、可解释）；生产演进 bge-m3 embedding + Chroma——**架构不变只换检索**。

### Q4：会话记忆怎么做的？
**要点**：assistants 表（conversation_id/role/content）→ 游客 localStorage 存 uuid → 每次请求带 id → 查历史拼进 messages → 滑动窗口/摘要压缩（>20 条）。

### Q5：SSE 和 WebSocket 区别？为什么选 SSE？
**要点**：单向（服务器→客户端）、HTTP 协议、自动重连、简单；WebSocket 双向。AI 流式回答 = 单向 → SSE 够用。

### Q6：怎么防别人刷你的 API（烧钱）？
**要点**：三层——Pydantic 长度限制（422）→ IP 限流内存版（10 次/分 429）→ 会话轮数（100 条）；**防护都在调 LLM 之前**；演进 Redis 分布式。

### Q7：部署踩过什么坑？
**要点**：OOM（2G 内存双 MySQL → 退役冗余 + swap）→ get.docker.com 被墙（阿里源）→ MySQL 首启超时（healthcheck 重跑）→ 容器缺依赖（requirements 漏 httpx/jieba）→ Docker COPY 不能引用 context 外文件。

### Q8：为什么工具要合并？LLM 选错工具怎么办？
**要点**：功能相近工具（标题搜索 vs 全文搜索）让 LLM 摇摆 → 合并成一个 search_knowledge（职责单一）→ description 写清使用边界——**实测中发现的真实问题**。

### Q9：生成器/事件流的异常处理？
**要点**：生成器异常在迭代时抛出 → try 包住 for 迭代 + done 收尾在 try 外 → 上游（DeepSeek）挂了返回友好提示不中断流。

### Q10：公共函数返回类型的设计教训？
**要点**：chat_completion 被 run_agent（要 message 对象）和摘要（要 content）两处用 → 返回语义不统一导致 KeyError → 统一返回 message 对象，调用方自取——**公共 API 设计教训**。
